# Typhoon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single-page web app on GitHub Pages that runs Cyclone-style power-zone rides on Ed's phone, reading live watts and cadence from a Wattbike over Web Bluetooth.

**Note (2026-10-31):** Spotify playback was removed. Tasks below that describe music, playlists, tempo lookup, a Spotify device, or a client id are historical build notes. They are not current product instructions. The living description is `docs/superpowers/specs/2026-10-28-typhoon-design.md`.

**Architecture:** Plain TypeScript with Vite, no UI framework. Pure helpers (one per file) hold every decision the app makes: zone lookup, FTP maths, Bluetooth byte parsing, interval timing, stat accumulation. Screen components render DOM into a root element and are switched by a hash router in `main.ts`. All state lives in browser local storage.

**Tech Stack:** Vite, TypeScript (strict), Vitest with jsdom, pnpm, Web Bluetooth (Cycling Power Service), GitHub Pages via GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-28-typhoon-design.md`

## Global Constraints

- pnpm only. TypeScript `strict: true`. Path alias `@/*` maps to `./*`.
- One function per file under `lib/`, default export, kebab-case filename matching the camelCase function name. Explicit return types everywhere. No barrel files. No relative imports.
- One `await` per `try/catch`, variables hoisted above the block.
- Components live in `components/<PascalCase>/index.ts` with a default export, `types.ts` beside them when they own types.
- Constants live in `lib/client/models/` using `as const`. Shared domain types live in `lib/client/models/types.ts`.
- Tests are Vitest, co-located (`foo.test.ts` beside `foo.ts`), Arrange / Act / Assert, `vi.clearAllMocks()` in `beforeEach`.
- Lengths: rides total exactly 1800 or 2700 seconds. Difficulty is 1 to 5.
- Zones (percent of FTP, colour): 1 = 0 to 55 grey, 2 = 56 to 75 blue, 3 = 76 to 90 green, 4 = 91 to 105 yellow, 5 = 106 to 120 orange, 6 = 121 to 150 red, 7 = 151+ purple.
- Default FTP is 150 W.
- FTP test factors: 60 s test = 0.70, 180 s = 0.80, 300 s = 0.85, 1200 s = 0.95.
- Units on screen: mph and miles.
- No in-app music. The Spotify and GetSongBPM instructions later in this plan are retired.
- No position cues and no coaching text on the ride screen.
- No em dashes anywhere, including copy and commit messages.

## Review Focus

1. **Crank counter rollover.** The cumulative crank revolution field is a 16-bit counter that wraps at 65535. Cadence must stay correct across the wrap, never negative or enormous. Pinned in Task 4.
2. **Rider stops pedalling.** Two notifications with the same last crank event time must yield cadence 0, never division by zero or NaN. Pinned in Task 4.
3. **Throttled timers.** Chrome slows timers in a backgrounded tab. Elapsed time must come from timestamps, so a 5 second gap between ticks advances the ride by 5 seconds and counts stats for 5 seconds. Pinned in Task 6.
4. **Music tasks are retired.** Task 8, Task 9, and the music parts of the ride screen are historical. A ride no longer plays or skips tracks.

### Task 4: Bluetooth byte parsing and cadence

**Files:**

- Modify: `lib/client/models/types.ts`

**Interfaces:**
- Produces in `types.ts`: `interface PowerMeasurement { watts: number; crankRevolutions: number | null; crankEventTime: number | null }` (event time in 1/1024 s units as broadcast).
- Produces: `parseCyclingPowerMeasurement(view: DataView): PowerMeasurement`.
- Produces: `cadenceFromCrankSamples(previous: PowerMeasurement, current: PowerMeasurement): number | null` in rpm, `null` when either sample lacks crank data.

- [ ] **Step 1: Write failing tests**

```ts
it('parses instantaneous power with no optional fields', () => {
  const view = new DataView(new Uint8Array([0x00, 0x00, 0xe7, 0x00]).buffer);
  expect(parseCyclingPowerMeasurement(view)).toEqual({ watts: 231, crankRevolutions: null, crankEventTime: null });
});

it('parses crank data after the pedal balance and wheel fields', () => {
  // flags: balance present (bit 0), wheel data (bit 4), crank data (bit 5) = 0x31
  const bytes = [0x31, 0x00, 0xe7, 0x00, 0x64, /* wheel */ 1, 0, 0, 0, 0, 0, /* crank revs 1000 */ 0xe8, 0x03, /* time 2048 */ 0x00, 0x08];
  const result = parseCyclingPowerMeasurement(new DataView(new Uint8Array(bytes).buffer));
  expect(result).toEqual({ watts: 231, crankRevolutions: 1000, crankEventTime: 2048 });
});

it('computes cadence from two crank samples', () => {
  const previous = { watts: 0, crankRevolutions: 100, crankEventTime: 0 };
  const current = { watts: 0, crankRevolutions: 103, crankEventTime: 2048 }; // 3 revs in 2 s
  expect(cadenceFromCrankSamples(previous, current)).toBe(90);
});

it('handles the 16-bit rollover of both counters', () => {
  const previous = { watts: 0, crankRevolutions: 65534, crankEventTime: 65000 };
  const current = { watts: 0, crankRevolutions: 1, crankEventTime: 1512 }; // 3 revs, 2048 ticks
  expect(cadenceFromCrankSamples(previous, current)).toBe(90);
});

it('returns 0 when the crank event time has not moved', () => {
  const sample = { watts: 0, crankRevolutions: 50, crankEventTime: 1024 };
  expect(cadenceFromCrankSamples(sample, sample)).toBe(0);
});

it('returns null without crank data', () => {
  const sample = { watts: 100, crankRevolutions: null, crankEventTime: null };
  expect(cadenceFromCrankSamples(sample, sample)).toBeNull();
});
```

- [ ] **Step 2: Run, expect failure.**

- [ ] **Step 3: Implement.** Layout per the Cycling Power Service spec: flags `uint16` LE at 0, instantaneous power `int16` LE at 2, then optional fields in order: pedal power balance (flag bit 0, 1 byte), accumulated torque (bit 2, 2 bytes), wheel revolution data (bit 4, 6 bytes), crank revolution data (bit 5, `uint16` revolutions then `uint16` event time). Rollover: `(current - previous + 65536) % 65536`. Cadence: `deltaRevs / (deltaTicks / 1024) * 60`, rounded.

### Task 12: Ride screen

**Files:**
- Create: `components/RideScreen/index.ts`, `components/RideScreen/types.ts`, `components/RideScreen/index.test.ts`, `lib/client/helpers/decide-music-action.ts` and test, `lib/client/helpers/request-wake-lock.ts`

**Interfaces:**
- Consumes: everything from Tasks 2, 4 to 9 and 11.
- Produces: `decideMusicAction(state: MusicState, zone: ZoneNumber, now: number, tracks: Track[], tempos: TempoCache, random: () => number): MusicAction` where `type MusicState = { track: Track | null; startedAt: number; zone: ZoneNumber }` and `type MusicAction = { kind: 'hold' } | { kind: 'play'; track: Track }`. Returns `play` when there is no current track; otherwise applies `shouldChangeTrack` with `(now - startedAt) / 1000` and picks with `pickTrack` excluding the current track.
- Produces: `requestWakeLock(): Promise<WakeLockSentinel | null>` (`null` where unsupported).
- Produces: `renderRideScreen(root: HTMLElement, ride: Ride): void`.

Behaviour of the ride screen:
- **Ready state**: shows the ride name, a "Connect bike" button (calls `connectWattbike`, saves the device name to settings, then shows the live watts so Ed can see it works), the first track picked for the first interval's zone with "No music" when Spotify is not connected, and a "Start" button enabled once the bike is connected. On entry it loads the playlist's tracks with `getPlaylistTracks(settings.spotifyPlaylistId)` and the tempo cache; a failure here means "No music" for the whole ride.
- **Riding**: on Start, records `startedAt = performance.now()`, plays the first track, starts a 250 ms `setInterval` tick and requests the wake lock. Each tick computes `elapsed = (performance.now() - startedAt) / 1000`, calls `intervalAtElapsed`, accumulates stats with `deltaSeconds` equal to the real time since the last tick and the latest bike sample if it is under 3 s old, else `null`. When the zone changes it calls `decideMusicAction` and executes `play` with `playTrack`. Every 2 s it polls `getPlayerState`; when `durationMs - progressMs < 10000` and no track has been queued for this play, it queues `pickTrack` for the current zone.
- Any rejected Spotify call sets the top band to "No music" and is not retried until the next zone change.
- **Layout** per the spec: top band track and countdown (coloured in the target zone's colour), middle band `renderRideProfile`, bottom strip watts (coloured by live zone), rpm, mph, avg mph, miles, time remaining.
- **Bluetooth drop**: on disconnect, the watts cell shows "Reconnecting", `reconnectWattbike` is retried every 3 s, samples resume on success. The clock never pauses.
- **Finish**: when `intervalAtElapsed` returns `null`, stops the tick, releases the wake lock, builds `summariseRide` (passing the average watts over the test interval when `ride.ftpTestSeconds` is set), appends it to history, and navigates to `#/summary/<id>`. For FTP test rides it first shows the proposed FTP from `calculateFtp` with "Save" and "Keep current" buttons; Save writes settings.
- An "End ride" button finishes early with the stats so far.
